# Curriculum Build Checklist

## Target and authority

- [ ] Ultimate capability target is explicit.
- [ ] Scope and out-of-scope areas are explicit.
- [ ] One progression order controls advancement.
- [ ] `AUTHORITY.md` and `CURRICULUM_SPEC.json` agree.

## Dependency architecture

- [ ] Every primary-spine dependency has a causal reason.
- [ ] Every branch has an exact start gate.
- [ ] Targeted activation, if allowed, records prerequisite debt.
- [ ] Single-thread fallback contains no prerequisite inversions.

## Resources

- [ ] Every core resource has a specific job.
- [ ] Deepening does not accidentally block progression.
- [ ] Reference resources are not treated as mandatory linear reading.
- [ ] Acquisition queue follows activation order.
- [ ] Resource inventory avoids uncontrolled duplication.

## Mastery

- [ ] Every core group has at least one observable exit criterion.
- [ ] Exit gates test capability rather than consumption.
- [ ] Independent reconstruction is present where appropriate.
- [ ] Failure boundaries / confusable neighboring concepts are tested where useful.

## Current-work alignment

- [ ] Current projects map onto groups without rewriting prerequisite authority.
- [ ] Concept transfer records classify exactness honestly.
- [ ] Research-grade work defers to the canonical Research & Evidence Standard.

## Tooling and artifacts

- [ ] Tools are installed only when needed.
- [ ] Generated work lives under `work/`.
- [ ] Source resources remain separate from generated artifacts.

## Closure

- [ ] `tools/validate_curriculum.py` passes.
- [ ] Manifest / hashes regenerated after final changes.
- [ ] No placeholder tokens remain in authoritative instantiated files.
