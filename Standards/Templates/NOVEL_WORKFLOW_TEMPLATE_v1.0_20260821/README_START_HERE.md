# Reusable Novel Writing Workflow

This pack is a **novel-building system**, not a fill-in-the-blanks plot generator.

It is derived from the working method used in *asleep in a field with no sky*: establish the book's governing artistic law first, design the reader's experience alongside the protagonist's experience, build a reference field by craft function, draft proof/anchor scenes before over-solving the plot, track structure and continuity explicitly, and revise against testable constraints.

The template is intentionally genre-neutral. A romance, literary novel, horror novel, speculative novel, mystery, historical novel, or hybrid can use the same workflow without inheriting the content or ontology of another project.

## The core principle

**Protect the book's identity before expanding the book's detail.**

A novel can survive provisional names, missing chapters, and an unfinished plot. It usually cannot survive repeatedly changing what kind of experience it is supposed to create.

## Start here

1. Fill `00_PROJECT_CHARTER.md`.
2. Fill `01_FRAME_LOCK.md` and explicitly list forbidden moves.
3. Fill `02_READER_EXPERIENCE_ARC.md`.
4. Build `03_REFERENCE_FIELD.md` by *craft function*, not plot resemblance.
5. Draft 2–5 anchor scenes using `templates/ANCHOR_SCENE_PACKET.md` before locking a whole outline.
6. Calibrate the discovered voice in `04A_VOICE_AND_PROSE_CALIBRATION.md`.
7. Open `workbooks/novel_bible_template.xlsx` and transfer only decisions that have actually been made.
8. Build macro movements, then sequences/chapters, then scene cards.
9. Draft prose in `/draft/`.
10. Run the revision gates in `08_REVISION_GATES.md` after each major section.
11. Record structural changes in `CHANGELOG.md` and update `CURRENT_STATUS.md`.

## Authority stack

When files disagree, use this order:

1. `01_FRAME_LOCK.md` — highest artistic authority.
2. `CURRENT_STATUS.md` — current phase, locked/provisional decisions, next action.
3. `workbooks/novel_bible_template.xlsx` — current concrete planning state.
4. Method documents — reusable craft guidance.
5. `/archive_previous_versions/` — provenance only; never active authority.

This hierarchy exists to prevent a common failure in large creative projects: an older planning document quietly overriding a later, better understanding of the book.

## The workflow in one line

**seed → law → reader experience → reference field → anchor scenes → voice calibration → surface life → structure → ledgers → draft → prose feedback → revision gates → canonical version**

## What the system refuses to do

- It does not force a three-act structure.
- It does not make every character a symbol.
- It does not treat reference works as plot-part suppliers.
- It does not mistake planning completeness for artistic certainty.
- It does not require one master timeline when the novel does not need one.
- It does not let a clever mechanism excuse scenes that fail as human life.
- It does not allow an outline to become more authoritative than the book's actual prose.

## Gate rule

Do not advance because a template is filled. Advance because the **gate condition** is satisfied.

A scene, character, or structural decision may remain provisional for a long time. The system should preserve uncertainty instead of inventing false certainty just to complete a spreadsheet.
